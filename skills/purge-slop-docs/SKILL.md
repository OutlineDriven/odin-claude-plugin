# Purge Slop Docs

Docs rot by accretion, because adding feels safe and removing feels risky. This skill removes. It owns the tree sweep and the deletion decision, and it borrows doctrine rather than restating it: the pruning and hierarchy vocabulary is `skills/writing-skills/SKILL.md`, the sentence-level tell catalog is `skills/unslop/SKILL.md`, and the certainty grading that governs any automatic edit is `skills/deslop/SKILL.md`.

## Scope the sweep

`glob` the tracked markdown, then exclude what the repo does not author: vendored trees, `node_modules`, generated API output, and any doc whose header marks it auto-generated. In this repo that exclusion is load-bearing, since `output-styles/benchmark.md` carries a do-not-modify marker and `output-styles/*.md` tails are regenerated by `scripts/sync-baseline.py`. Report the file count before touching anything.

## Four defect classes, each with its own evidence test

A finding without its test is an opinion:

| Class | Test that makes it a finding | Default action |
|---|---|---|
| Overstatement | The sentence claims a property the repo cannot show: a benchmark with no number, a guarantee with no enforcing check, a superlative. Named in `unslop` as puffery, vague attribution, and generic conclusion. | Rewrite to the claim the evidence supports, or cut the sentence. |
| Jargon | A plainer word carries the same meaning, or the term is a metaphor noun standing in for a mechanism. `unslop` carries the substitution list. | Substitute the plain word. Keep a term that is the project's own vocabulary. |
| Outdated | The doc names a path, symbol, flag, command, or version that no longer resolves. Prove it: `read` the path, `grep` the symbol, or run the command. An unresolvable reference is HIGH certainty; a stale-sounding sentence with a resolving reference is LOW and stays. | Update to what resolves, or cut the section when nothing does. |
| Redundant | The same meaning exists in a second place, or the line restates what the environment already says (a `package.json` script, a config file, `--help` output). `writing-skills` calls the second one a cache that does not earn its load. | Keep one owner, point at it from the other site, delete the copy. |

## Certainty gate before any edit

Mirror the `deslop` contract rather than inventing one: HIGH means a deterministic check proved it, so the fix is applied; MEDIUM and LOW are reported and not touched. Certainty is not severity, so a trivial stale path is HIGH and a suspicious paragraph is LOW.

## Deleting a whole doc needs a yes

A doc is a deletion candidate when nothing references it and every section failed a class test. That is a surface removal, so name the file, name what referenced it (nothing), and ask. Never batch several deletions into one question.

## Hierarchy reordering, owned here

This skill is the single owner of the reorder, and `sync-docs` reaches it rather than carrying a copy. Two operations, using the ladder in `skills/writing-skills/SKILL.md` (in-file step, in-file reference, disclosed reference):

1. Within a file: move material to its right rung, and co-locate a concept's definition, rules, and caveats under one heading rather than scattered. Push reference only some branches reach behind a pointer, and inline what every branch needs.
2. Across the tree: the entry doc states what the project is and where to start, and detail sits behind pointers from it. A doc reachable by no pointer is either the entry doc or a deletion candidate.

The gate on every reorder: each pointer still resolves afterwards. A reorder that leaves a dangling pointer is worse than the sprawl it fixed, so check every link and path the move touched before reporting done.

## Report

Counts per class, edits applied against findings reported, every deletion with its yes, and the pointer check result.

## Boundaries

- One document's voice and rhythm goes to `unslop`.
- Code debris goes to `deslop`.
- Drift traced from a specific diff goes to `sync-docs`.
- A skills-tree rule dedup goes to `dedup-skills`.
- Judgment slop goes to `taste`.
