# Quality checklist reference

Use this checklist to evaluate every README before finalizing. Fix each failing item before declaring the skill done.

## Structure

- [ ] Opens with a clear project name and one-line tagline
- [ ] Contains a visual separator after the shop-window
- [ ] Installation section is present and accurate
- [ ] Quick Start section is present and runnable
- [ ] Features section is present
- [ ] Usage section is present
- [ ] Contributing section is present
- [ ] License section is present

## Content

- [ ] Installation instructions are accurate and complete for the project's package manager
- [ ] Quick Start commands are copy-pasteable and produce a working result
- [ ] Features describe what the user can do, not implementation details
- [ ] Usage examples are real and tested
- [ ] Contributing section names the workflow (fork, branch, test, PR)
- [ ] License section names the license and links to the full text

## Accuracy

- [ ] No commands that require non-standard tools beyond those listed in Installation
- [ ] No hardcoded paths that differ from the project's actual structure
- [ ] No version numbers that contradict the project manifest
- [ ] No claims about features the project does not have

## Presentation

- [ ] Badge images load and display correctly
- [ ] No broken relative links
- [ ] Code blocks have language tags
- [ ] No overly long paragraphs; break them up
- [ ] Consistent heading levels
