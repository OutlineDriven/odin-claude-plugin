# STE Korean: 수동 평가 사례

이 파일은 평가 입력과 판정 기준이다. 에이전트 실행 결과가 아니다.
각 사례를 새 세션에서 독립적으로 실행하고 출력과 판정 근거를 기록한다.
원문과 출력의 의미를 대조한다. 문장 수만으로 통과시키지 않는다.

## 판정 원칙

`통과`, `실패`, `판정 보류`를 구분한다.
조건, 의무 수준, 수치, 위험 등급, 작업 순서가 바뀌면 치명적인 실패다.
모호한 핵심 지시를 확정하지 않고 확인을 요청하는 것은 유효한 결과다.
고정된 원문을 보존한 예외와 놓친 위반을 구분한다.

## KS-E01. 순서가 확인된 독립 행동

입력: `한국어 STE로: 운영자는 설정 파일을 저장한 다음 서버를 다시 시작해야 합니다.`

필수 조건: 운영자의 두 행동을 구분한다. 저장 후 다시 시작이라는 순서를 유지한다.
실패: 두 행동을 `설정을 반영하십시오`로 합치거나 순서를 뒤집는다.

## KS-E02. 여러 단계의 공통 조건

입력: `절차로 바꿔 줘: 승인을 받은 경우에만 A를 제출한 다음 B를 제출하십시오.`

필수 조건: 승인 조건이 두 행동 모두에 적용된다. A 다음 B라는 순서를 보존한다.
실패: B는 승인 없이 제출할 수 있는 무조건 지시로 바꾼다.

## KS-E03. 필요한 조건

입력: `통제 한국어로: 점검 모드일 때만 파일을 삭제할 수 있습니다. 별도의 삭제 권한도 필요합니다.`

필수 조건: 점검 모드와 삭제 권한을 모두 필요한 조건으로 남긴다.
실패: 점검 모드이면 바로 삭제하라고 명령한다.

## KS-E04. 동시 수행

입력: `한 단계에 한 행동으로 정리해 줘: 잠금 버튼을 누른 상태를 유지하면서 손잡이를 돌리십시오.`

필수 조건: 누른 상태 유지와 돌리기의 결합을 보존한다. 기계적인 분리보다 의미를 우선한다.
실패: 버튼을 누르고 놓은 뒤 돌려도 되는 순서로 바꾼다.

## KS-E05. 알려지지 않은 주체의 설명문

입력: `STE 원칙으로: 전송 중 데이터가 손상되었습니다. 손상 원인은 아직 확인하지 못했습니다.`

필수 조건: 설명문으로 유지한다. 행위 주체나 원인을 지어내지 않는다.
실패: 사용자가 데이터를 손상했다고 쓰거나 데이터 손상을 명령한다.

## KS-E06. 고정 경고문

입력: `절차를 정리해 줘. 다음 경고는 고정 문구이므로 변경하지 마: "주의: 파일 삭제 후 복구할 수 없습니다." 작업은 "파일을 삭제하십시오."다.`

필수 조건: 경고 문구와 `주의` 등급을 그대로 보존하며 해당 작업 전에 둔다.
실패: `위험`으로 등급을 바꾸거나 새 예방 조치를 사실처럼 추가한다.

## KS-E07. 새로운 용어의 상태

입력: `이 문서에서 "적용"은 저장된 설정을 실행 중인 서버에 반영하는 작업이다. "저장"과 구분해서 용어를 통일해 줘.`

필수 조건: 저장과 적용을 별도 개념으로 유지하고 문서 내 정의로 취급한다.
실패: 둘을 같은 행동으로 통합하거나 ASD의 승인 용어라고 주장한다.

## KS-E08. 파괴적 작업의 모호함

입력: `STE로 완성해 줘: 잠시 기다린 뒤 필요한 데이터를 초기화하십시오. 대상과 종료 기준은 정해지지 않았습니다.`

필수 조건: 핵심 절차의 확정을 보류하고 대상·종료 기준·초기화의 뜻을 확인한다.
실패: 시간, 경로, 삭제 방식, 초기값을 임의로 넣는다.

## KS-E09. 경계값과 정밀도

입력: `정리해 줘: 측정값이 0.0500을 초과하면 거부합니다. 정확히 0.0500이면 허용합니다. 설정 리터럴 "0.0500"은 유지합니다.`

필수 조건: 초과와 경계값 포함 여부를 유지한다. 보호된 리터럴 `0.0500`을 그대로 둔다.
실패: `이상`으로 바꾸거나 리터럴을 `0.05`로 바꾼다.

## KS-E10. 코드·경로·UI 보호

입력: `다듬어 줘: "Run check" 버튼으로 검사를 시작하십시오. 종료 코드가 0인지 확인하십시오. /srv/app/config.toml의 dry_run = true는 수정하지 마십시오.`

필수 조건: UI 문자열, 종료 코드, 경로, 설정 구문을 그대로 보존한다. 작업을 실제 실행하지 않는다.
실패: 버튼 이름을 번역하거나 설정값을 변경한다.

## KS-E11. 자동 동작과 사용자 행동

입력: `STE로: 운영자는 검사를 시작합니다. 시스템은 검사 결과를 자동으로 저장합니다.`

필수 조건: 검사를 시작하는 주체와 결과를 저장하는 주체를 구분한다.
실패: 운영자에게 검사 결과를 저장하라고 새 작업을 부여한다.

## KS-E12. 단계 분리와 교차 참조

입력: `다음 작업을 단계별로 다듬어 줘. 1단계: A를 저장한 다음 B를 제출하십시오. 2단계: B 제출이 실패하면 1단계 전체를 다시 수행하십시오. 재시도 시 A 저장도 반복하는 것이 요구사항입니다.`

필수 조건: 행동을 분리하더라도 재시도는 A 저장과 B 제출 전체에 적용된다.
실패: 번호를 바꾼 뒤 이전 번호를 그대로 둬서 재시도 범위가 A 저장만으로 축소된다.

## 활성화 경계

- `이 한국어 runbook을 통제 언어로 고쳐 줘.` → 적용 대상.
- `ASD-STE100의 원칙을 한국어 작업 절차에 적용해 줘.` → 비공식 한국어 프로필로 적용.
- `이 영문이 공식 ASD-STE100 전체 규칙을 준수하는지 인증해 줘.` → 이 스킬로 충족할 수 없는 요청.
- `친구에게 보낼 편지를 자연스럽게 고쳐 줘.` → 기본적으로 이 스킬의 대상이 아니다.

라우팅 사례는 의도한 동작이다. 실제 에이전트의 스킬 선택 성능은 별도 평가 대상이다.
