# Ninja cheatsheet

Source: <https://ninja-build.org/manual.html>. Grounded against Ninja 1.13.2.

## Command line

```bash
ninja                    # build the default target
ninja myapp              # build one target
ninja clean              # remove outputs (same as -t clean)

ninja -j4                # exactly 4 parallel jobs
ninja -j"$(nproc)"       # one job per CPU
ninja -j0                # unlimited jobs
ninja -l4.0              # no new jobs while load average exceeds 4.0
ninja -k5                # stop after 5 failures
ninja -k0                # keep going regardless of failures

ninja -v                 # verbose: full command lines
ninja -n                 # dry run
ninja -C build/          # chdir first
ninja -f file.ninja      # alternate manifest

ninja -d explain myapp   # why a target rebuilds
ninja -d keepdepfile     # keep .d files after reading
ninja -d keeprsp         # keep @response files
ninja -d stats           # print statistics at the end
```

## Sub-tools (-t)

```bash
ninja -t targets           # targets by rule or depth
ninja -t targets all       # including intermediates
ninja -t targets rule cc   # targets using rule cc

ninja -t clean             # remove built files
ninja -t clean myapp       # clean one target
ninja -t clean -g          # also remove generated files

ninja -t query myapp       # inputs and outputs of one edge
ninja -t graph myapp | dot -Tsvg -o deps.svg
ninja -t compdb cc cxx > compile_commands.json
ninja -t rules             # all rules
ninja -t commands myapp    # commands needed to rebuild a target
ninja -t inputs myapp      # all inputs of a target
ninja -t deps              # deps-log dependencies
ninja -t missingdeps       # generated-file deps missing from the graph
ninja -t cleandead         # remove outputs no longer produced
ninja -t recompact         # compact internal data structures
ninja -t restat            # restat outputs in the build log
ninja -t browse --port=8080 myapp   # web dependency browser
```

## build.ninja format

Ninja files are generated by CMake, Meson, or another tool. Read them to debug;
edit the generator input, not the manifest.

```ninja
cc = gcc
cflags = -Wall -O2

rule compile_c
  command = $cc $cflags -c $in -o $out
  description = CC $in
  depfile = $out.d
  deps = gcc              # read gcc-style .d depfiles

rule link
  command = $cc -o $out $in
  description = LINK $out

build src/foo.o: compile_c src/foo.c
build src/bar.o: compile_c src/bar.c
build myapp: link src/foo.o src/bar.o

build clean: phony
build all: phony myapp
default all
```

| Concept | Meaning |
|---|---|
| `rule` | Command template |
| `build` | Edge instantiating a rule on files |
| `$in` | Edge inputs, space-separated |
| `$out` | Edge outputs, space-separated |
| `depfile` | Makefile-style `.d` path |
| `deps = gcc` | Parse gcc depfiles into the deps log |
| `deps = msvc` | Parse MSVC `/showIncludes` output |
| `phony` | Always out of date, like `.PHONY` |
| `default` | Built when no target is named |

## Variable scoping

```ninja
cflags = -O2                  # global

rule compile_c
  command = gcc $cflags -c $in -o $out
  cflags = -O0                # shadows the global inside this rule

build slow.o: compile_c slow.c
  cflags = -O0 -g             # applies to this edge only
```

Response files for long command lines:

```ninja
rule link
  command = gcc @$out.rsp -o $out
  rspfile = $out.rsp
  rspfile_content = $in $LINK_FLAGS
```

## With CMake

```bash
cmake -S . -B build -G Ninja
cmake --build build
cmake --build build -- -j"$(nproc)"   # pass flags through to ninja
cmake --build build -- -v             # verbose
cmake --build build --target myapp
cmake --build build --target clean

cmake -S . -B build -G "Ninja Multi-Config"
cmake --build build --config Release

cmake -S . -B build -G Ninja -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `missing and no known rule` | Source absent from the manifest | Regenerate; check the generator's source list |
| Stale build | `build.ninja` outdated | Re-run the configure step |
| `build stopped: subcommand failed` | A compile or link failed | `-v` shows the failing command |
| Interleaved parallel output | Many jobs writing at once | `ninja -j1` serializes; `pool console` serializes one rule |
| Circular dependency | Indirect self-dependency | Check the generator's dependency declarations |
| Slow incremental build | Redundant edges or glob churn | `ninja -d explain` shows what is dirty and why |

```bash
ninja -d explain myapp 2>&1 | head -30
# prints which input is newer than the target and forces the rebuild
```
